8.20 Blackboard Rules
The Blackboard stores only temporary cognitive state.
Long-term facts belong in Memory, not the Blackboard.
Every entry has a lifetime (TTL).
Attention limits what enters Working Memory.
Hypotheses are separate from facts.
Evidence changes confidence, not truth directly.
All reasoning-capable modules use the Blackboard for collaboration.
The Blackboard is cleared or pruned as tasks complete.
Updates are event-driven and traceable.
The Blackboard is the only shared workspace for active cognition.

Notice that Critical Thinking and Reasoning are now separate stages. That distinction is intentional:

Reasoning generates and evaluates possible conclusions.
Critical Thinking challenges those conclusions, looks for missing evidence, tests assumptions, and searches for alternative explanations before a decision is finalized.

Critical Addition Before Step 9

This is where I'd introduce a component that many AI systems lack:

Meta-Cognition (Thinking About Thinking)

So far, Aariya can:

Remember
Plan
Manage goals
Build a world model
Maintain working memory

But it still doesn't evaluate its own reasoning process.

A Meta-Cognition layer would monitor:

Confidence in conclusions
Signs of conflicting evidence
Whether more information is needed
Whether a different reasoning strategy would be better
Whether to ask the user a clarifying question instead of guessing

This supervisory layer helps prevent overconfidence and improves decision quality.

9.22 Rules
Never confuse assumptions with facts.
Confidence is earned through evidence.
Always consider alternatives before major decisions.
Ask for clarification when evidence is insufficient.
Reflection happens after significant outcomes.
Reasoning strategies are selected based on the problem.
Decision audits are retained for transparency.
Bias detection informs the process but does not replace evidence.
Meta-Cognition supervises; it does not execute tasks.
Learning adjusts future reasoning strategies rather than rewriting core architecture automatically.

10.22 Executive Rules
The Executive is the only component that controls the full cognitive cycle.
It coordinates capabilities but does not replace them.
All execution decisions pass through policy and permission checks.
It chooses the appropriate reasoning depth based on task complexity.
It can interrupt, suspend, or resume goals.
It continuously monitors system health and recovery.
It triggers reflection after significant outcomes.
It keeps cognition explainable by recording why decisions were made.
It avoids unnecessary computation by selecting only the capabilities needed.
It is deterministic in control flow, while allowing nondeterministic reasoning inside reasoning modules.

11.4 Universal Skill Interface
from abc import ABC, abstractmethod

class Skill(ABC):

    @property
    @abstractmethod
    def metadata(self):
        """Return immutable skill metadata."""
        ...

    @abstractmethod
    async def validate(self, request):
        """Validate input schema and permissions."""
        ...

    @abstractmethod
    async def execute(self, request):
        """Run the skill."""
        ...

    @abstractmethod
    async def health(self):
        """Return health/availability."""
        ...

Notice that skills do one thing.

STEP 12 — Reasoning Strategy Engine (Choosing How to Think)

This is one of the most important architectural additions in the entire Aariya Cognitive OS.

Up until now, we've built:

Memory (stores knowledge)
World Model (understands reality)
Blackboard (working memory)
Critical Thinking (evaluates ideas)
Executive (controls cognition)
Planner (creates plans)
Skill Framework (executes actions)

But there is still one missing question:

Before planning, how should Aariya think?

Different problems require different reasoning strategies.

This is the job of the Reasoning Strategy Engine (RSE).

Aariya Core Interface Architecture
1. Capability Interface

Purpose: A standardized unit of ability.

Examples:

Search web
Solve math
Analyze image
Control avatar
Retrieve memory
Run OSINT investigation
from abc import ABC, abstractmethod
from typing import Dict, Any


class Capability(ABC):

    @property
    @abstractmethod
    def name(self) -> str:
        pass

    @property
    @abstractmethod
    def version(self) -> str:
        pass


    @abstractmethod
    async def execute(
        self,
        input_data: Dict[str, Any],
        context: Dict[str, Any]
    ) -> Dict[str, Any]:
        """
        Execute capability
        """
        pass


    @abstractmethod
    async def health_check(self) -> bool:
        pass

Example:

VisionCapability
    |
    ├── ImageDetection
    ├── FaceAnalysis
    └── SceneUnderstanding
