🧩 States
State	Meaning
LISTENING	User speaking, AI silent

RESPONDING	AI speaking

YIELDING	AI stops because user interrupted

🔄 State Transitions
1. LISTENING

Enter when: vad_user == speech

Actions:

accumulate turn_length_ms

enable backchannel timer

Transitions:

→ BACKCHANNEL_READY
if:

turn_length_ms > 1200 ms
AND prosody_energy high
AND trust_level > 0.3


→ PROCESSING
if:

vad_user → silence

2. BACKCHANNEL_READY

This is a micro-state, lasts one tick.

Action:

trigger nod / “mm-hm” (no LLM)

return to LISTENING

Rate limit:

min_interval = lerp(6s → 2s based on trust)

3. PROCESSING

This is the human pause window.

Start timer: silence_ms = 0

We wait before speaking to avoid cutting in.

Dynamic wait:

base_wait = 220 ms
+ 0.15 * last_turn_length
+ trust_modifier


Where:

Trust	Modifier
Low	+180 ms
Mid	+80 ms
High	+0 ms

Transitions:

→ RESPONDING
if:

silence_ms > wait_time
AND router_mode != DEFER


→ LISTENING
if user resumes speech

4. RESPONDING

AI speaking.

Monitor:

if interruption_flag == true:
    → YIELDING


Also:

send vad_ai = speaking to router

block new responses

5. YIELDING (Barge-In Handling)

Triggered when user starts talking while AI is speaking.

Actions:

stop TTS immediately (stop_tts event)

play quick acknowledgment animation

reset timers

Transition:

→ LISTENING

Trust effect:

At low trust, AI yields faster:

barge_in_threshold = 50 ms


At high trust, slightly slower (more assertive):

barge_in_threshold = 120 ms

6. HOLD (Deliberate Pause)

Used for:

dramatic timing

emotional responses

high-trust intimacy pacing

Enter from PROCESSING if:

intent in {COMFORTING, TEASING}
AND trust_level > 0.6


Hold duration:

300–900 ms (scaled by arousal)


Then → RESPONDING

  case LISTENING:
    if (vad_user) accumulateTurn()
    if (backchannelEligible()) emitBackchannel()

function computeTurnReward(O) {
